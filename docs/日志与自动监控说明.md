# 修改器日志与自动监控说明

版本：26049821.4；适配 Steam App ID 3337140 / 游戏构建 26049821。

## 使用

直接启动 AfterIncRevivalTrainer_CN.exe，监控自动启动，无需另开脚本。每次启动在 EXE 旁的 logs 文件夹建立独立子目录，名称含本地日期、时间、进程号和随机后缀。
默认发布位置为 G:/Trainer/after_inc_trainer/dist/logs。
点击修改器“打开日志目录”可直接进入本次会话目录。关闭后日志保留；下次启动创建新目录。

## 记录内容

- events.0000.log 等：UTF-8，每行一个 JSON 对象，带本地时间与时区。
- session_start：修改器版本、PID、游戏 App ID、支持构建和本次日志路径。
- toggle：人力等资源锁定、战士快速移动、队伍保持的开关变化。
- operation_start / operation_complete / operation_error：资源修改、远征日期、添加/清除地图、队伍、战士操作的参数、返回结果或异常；相同 id 可关联开始与结果。
- resource_write_verified：资源修改前后字节、目标值、游戏 PID，区分手动修改和持续锁定。
- write_conflict：写入被游戏抢占时的现场记录；含地址、写入前字节、期望字节、实际读回字节（空值表示读回失败）和已重试次数。持续锁定会自动重试，手动设置弹出提示。
- memory_scan.write_memory 的操作记录：写入地址、字节长度和最多前 64 字节；每次持续锁定的写入也记录。
- process_snapshot：约每 3 秒采集游戏、修改器与 Unity 崩溃处理进程的 PID、父进程、启动时间、CPU 累计用量、内存、路径和可读取的状态。采集耗时会使实际间隔变长。
- game_player.0000.log 等：Unity Player.log 的增量内容。启动先收集现有日志末尾最多 64 KiB，之后每次最多读取 1 MiB；发现轮换或缩短后从头读取。
- operations 子目录：原有详细操作报告统一放在本次会话内。持续修改的完整时间线以 events 文件为准。
- ui_status / ui_exception / worker_error / monitor_error：界面反馈、界面异常、未处理后台异常和采集错误。
- close_requested / workers_finished / session_end：关闭请求、后台操作收尾和正常退出。

## 关闭行为

点击窗口关闭后停止发起新的修改与采样，取消持续锁定、快速移动和队伍保持。已有后台操作仍会完成；窗口显示“等待当前操作完成并恢复游戏运行”。待后台线程完成后退出并写入 session_end，监控随修改器一起结束，没有独立遗留的监控进程。
这能避免正常关闭恰好截断暂停/恢复游戏的操作，但不等于卸载已注入游戏的扩展，也不撤销已有修改、远征地图或修复问题存档。
任务管理器强制结束、断电或程序崩溃无法保证执行收尾；缺少 session_end 可作为异常退出线索，不能单凭此认定原因。

## 日志保存与排查

日志只存本地，不上传。events 和 game_player 到约 8 MiB 后续写下一编号文件，不删除旧分片；历史会话也不自动删除，可在修改器关闭后手动归档清理。
无法创建日志目录时会提示并停止启动；运行中事件日志写入失败会在状态栏提示。磁盘已满或强制结束可能导致记录不完整。
日志不是存档备份。添加远征前的自动备份仍在 %LOCALAPPDATA%/AfterIncTrainer/backups，不会因关闭修改器而删除。
进程 CPU 和状态采样不等于窗口响应检测，也不能单独证明死锁；游戏日志快速轮换或崩溃未落盘时可能缺失片段。
排查时提供出问题那次启动的整个会话子目录，并说明操作顺序和大致时间。不要只截取最后一行。
